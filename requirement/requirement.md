# Golang Migration

# Context
This document outlines the requirements for migrating a project from Python to Golang. The primary goal is to ensure that the migration process is smooth and efficient, while maintaining the functionality and performance of the application.


# Goals
- Migrate the project from Python to Golang.
- Ensure that the migration process is smooth and efficient.
- Maintain the functionality and performance of the application.
- Use best practices for Go development.
- Use modern tools and libraries for Go development.
- Use a version control system for the project.
- Use a testing framework for the project.
- Use a dependency management system for the project.
- Use a software development lifecycle for the project.
- Use a database for the project.
- Use a containerization system for the project.
- Use a CI/CD pipeline for the project.
- Use a logging system for the project.
- Use a monitoring system for the project.
- Use a configuration management system for the project.
- Use a security system for the project.
- Use a performance monitoring system for the project.
- Use a load testing system for the project.
- Use a Unit test.

# Technology Stack
- Golang
- Database: Postgres
- Testing Framework: GoTest
- Software Development Lifecycle: TDD
- Dependency Management: Go Modules
- Version Control: Github

# Tools
- Docker
- Docker Compose
- Github Actions

# Workflow Feature Development
- Investigate the project and understand the requirements
- Identify the key components and their dependencies
- Design the migration plan
- Breaking down the migration into smaller steps
- Use any tools or mcp to help with the migration
- Delegate to the specific subagents to help with the migration
- Can spawn as many as subagents as needed
- Create a branch first when working on 1 task
- Create test cases for the migration (TDD)
- Working on the migration phase by phase
- Self update document
- Create pull request of the 1 task and merge it into branch called golang_master

# Workflow Bug or Issue Fix
- Investigate the issue
- Identify the root cause
- Create a test case to reproduce the issue
- Create a branch to fix the issue
- Fix the issue
- Create a test case to verify the fix
- Document the problem and the fix as for the future reference of the same problem in the future
